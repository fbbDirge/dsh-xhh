# 更新日志

按版本倒序记录功能变化、修复与验证范围。安装和使用说明见 [项目首页](../README.md)，详细配置见 [配置说明](configuration.md)。后续版本记录统一维护在本文档。

## 0.12.1 回复自己帖子的评论

「互动 → 回复来信」新增「自动回复自己帖子的评论」开关，需要同时开启「自动回复评论」。核实当前账号是帖子作者后，回复其他用户直接发表的顶层评论；适用于插件发布和手动发布的帖子。自己评论和其他用户之间的对话会被过滤；后续明确回复当前账号的来信仍走原自动回复流程。

可选择使用回复人格，或沿用发帖人格：后者优先取该帖发帖记录中的人格，没有记录则取当前发帖人格。记录显示回复对象类型与人格来源。复用现有消息检查频率、持久化队列、额度、冷却、失败重试和发送去重；默认关闭，升级不主动扩大发言范围。依赖平台消息通知，不会扫描自己所有历史帖；真实账号的通知字段与公开回复仍待验收。

## 0.12.0 提示词控制发帖时间

「发帖 → 发帖时间方式」新增「提示词规划时间」。例如填写“每天在午休或晚间选择 1–2 个不固定时间，周日不发”，并设置每日上限及最短间隔。宿主首次开启和每天跨天后，让模型规划当天剩余时间，保存后到点再生成正文并发布；时间规划和正文生成都使用高级设置中的模型及独立发帖人格。正常每天规划一次，宿主每 5 秒检查本地时间，不会反复请求模型。保留原固定时间模式，升级不会自动切换或开启。

「时间规划记录」可查看安排、未安排、失败和重试状态。计划按账号持久化，重启沿用；修改时间提示词从下一天生效，降低每日上限或增大间隔会约束剩余任务。无效计划最多尝试 3 次，间隔至少 5 分钟，当日失败后不发帖。模型允许选择当天不发；自然语言条件由模型理解，宿主强制校验数量、未来时间和最短间隔。详见 [提示词时间规划](configuration.md#提示词时间规划0120)。

## 0.11.1 发帖分区与话题

「设置 → 刷小黑盒 → 发帖 → 发帖分区与话题」支持登录后按名称搜索、选择和移除目标。最多选择 2 个分区、5 个话题，其中活动话题最多 1 个；搜索词留空可读取平台推荐。选择完成后点击保存，定时发帖会提交所选分区与话题，并在生成时参考它们，继续遵守独立发帖人格。

旧版手填社区 ID 保持兼容；通过搜索选择分区后自动清空旧 ID。本次任务开始时固定分区和话题，后续编辑设置不会改变待重试任务的发布目标。话题标签与「发帖主题与要求」分开配置。查询和发布接口已通过模拟测试，尚未进行真实账号公开发布验收。

## 0.11.0 独立人格定时发帖

新增「发帖」Tab，可单独设置发帖人格、主题、社区 ID、时区和单次 / 每天 / 每周发布时间。使用高级设置中的模型来源，到期生成文字帖子并提交；发帖人格不继承评论或回复人格。默认关闭，升级不会自动发帖。

任务按账号和时间槽持久化，重启不重复发送；生成失败最多尝试 3 次。超过计划时间 10 分钟记为错过，发送结果未知不自动重发。记录显示生成正文、帖子链接与读取核验结果。当前通过离线模拟测试，尚未使用真实账号验收公开发布；平台签名、社区权限及公开可见性仍需联调。

## 0.10.9 每日额度上限

每日评论与每日回复额度均支持 0–9999，默认仍各为 10，升级保留已设额度。额度按发送尝试统计，仍遵守发送冷却、调度与平台限制。

## 0.10.8 深层评论查找修复

修复来信位于楼中楼第 6 页及以后时反复提示「暂未找到完整评论关系」的问题。每轮仍最多查 5 页，但分页进度保存到待回复队列，下轮从上次位置继续，重启也保留进度；查到底仍未找到时重置，后续可重新查找。回复前仍核对评论归属，不保证已删除或不可访问的评论能够回复。

## 0.10.7 自定义提及兼容

核对旧补丁脚本的小黑盒功能：评论 / 回复创建所需的 Workshop v15 `_rnd` 签名及新版参数已内置，无需额外打补丁。新增「互动 → 评论帖子 → 缺少 ID 时允许纯文本 @」，默认关闭；开启后，自定义用户未填 ID 时可以发送普通 `@昵称`，避免旧配置阻断该条评论。纯文本不绑定用户，不能保证通知到对方；填写 ID 时仍优先生成用户链接。该选项仅影响帖子评论，不影响按评论 ID 定位的回复。

## 0.10.6 待回复队列

发现的待回复来信先按账号保存在本地 `automation.json`。例如收到 10 条、每轮限制 5 条，剩余 5 条留到下轮；生成失败、暂时取不到完整评论关系或平台明确拒绝发送时也保留，下轮按设置继续。重启、来信变为已读或不再出现在消息列表中，不会清除已经入队的记录。「评论记录」新增队列，显示尝试次数、最近原因和待确认状态。

重试仍受开关、每日额度、冷却和运行时段限制，每次实际发送尝试都占每日额度；额度耗尽保留到次日。发送结果未知时保留为待确认，请先到平台核对，不自动重发；已发送、已受理、模型决定跳过或确认并非回复自己的评论时结束处理。旧版未入队的拒绝记录不会批量补发。详细行为见 [失败与积压回复队列](configuration.md#失败与积压回复队列0106)。

## 0.10.5 评论发送修复

修复 [Issue #1](https://github.com/fbbDirge/dsh-xiaoheihe/issues/1)：评论和回复的创建请求使用新版网页参数及 `_rnd` 附加签名，解决旧请求可能被返回“缺失参数”的问题。浏览接口不变。平台失败响应的 HTTP 状态、业务状态与原因经敏感信息过滤后保存在评论记录中，便于排查。

该版本产生的拒绝或发送结果未知记录继续去重，升级不会自动补发。0.10.6 起新入队回复的明确拒绝会重试，结果未知仍不自动重发。新增请求构造与错误处理测试均为离线模拟；提交者报告新版参数可真实发送，维护者尚未完成独立真实账号复验，不代表已验证 @ 通知。

## 0.10.2 用户提及链接

将普通 `@昵称` 改为包含 `data-user-id` 与 `openUser` 协议的提及链接。自定义用户需补充数字 ID；旧配置保留，缺少 ID 时跳过发送并记录错误。标记来自用户提供的官方客户端显示样本，实际提交与通知仍需平台联调。

## 0.10.0 自定义提及与第三方模型

新增自定义 @ 昵称、第三方模型 API 和独立配置 JSON 编辑，使用方法见 [配置说明](configuration.md)。第三方模型同样使用通用人格 / 回复人格；提及通知仍未完成平台端验证。
