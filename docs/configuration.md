# 配置、提及与第三方模型

## 自定义 @

原实现只有 `mentionAuthor` 开关；把 `@昵称` 写进人格也不会成为可靠提及，因为模型输出校验会拒绝额外 `@`。现在在「互动」开启「评论时添加 @ 提及」，再选择帖子作者、自定义昵称或不提及。自定义支持 `昵称` 和 `@昵称`，保存时统一去掉前缀再由宿主拼接。此设置影响帖子评论；评论回复仍通过平台 `reply_id/root_id` 指向来信。

官网评论提交使用 `text` 字段，当前尚未验证原生提及通知协议。因此只能保证所选昵称进入评论正文，不能保证该用户收到 @ 通知。不要把昵称、用户 ID 或未经验证的标记伪装成已实现的原生通知。

## 第三方 API

「高级 → 模型来源」选择第三方 API，填写兼容 Chat Completions 的 Base URL、模型名和 API Key。例如 Base URL 为 `https://api.example.com/v1` 时，调用 `/v1/chat/completions`；完整端点也支持。远程地址使用 HTTPS，本机 localhost / 127.0.0.1 / ::1 可用 HTTP。只支持非流式文本输出，不提供工具或发送小黑盒 Cookie。

两种模型来源共用相同提示词与结果校验。帖子评论使用「通用人设与兴趣」，回复使用「回复人格」，空白回复人格沿用通用人格。人格放入 system 消息，帖子和评论作为不可信的 user 数据传入。模型只决定 send / skip 与正文；提及、额度、去重、冷却和平台发送均由宿主控制。提示词约束不能保证任意第三方模型完全遵守人格，需根据实际输出调整模型和设定。

API Key 保存在服务器配置文件，状态接口不返回密钥；表单留空保留已有密钥，显式点击清除可删除。第三方请求禁止跟随重定向，不自动重试；错误记录只保留本地错误说明及 HTTP 状态，不记录上游响应正文。

## 编辑配置文件

独立配置位于 `$DSH_HOME/heybox/config.json`，默认 `~/.dsh/heybox/config.json`，首次从旧 automation.json 自动迁移。文件权限 0600。密钥仅保存在该文件；浏览历史与发送记录仍位于 `automation.json`，不会写入 B 站目录。

可在「高级 → 配置文件」打开 JSON 快照，修改后点击「保存配置文件」。快照不包含已有 apiKey；省略该字段会保留密钥，`"apiKey": ""` 会清除。此操作会同步表单并覆盖尚未保存的表单修改。也可直接编辑服务器文件，建议停止当前任务后用临时文件加 rename 的方式原子替换；设置在下次调度读取，已计算的下一次运行时间仍沿用，界面保存设置会重新计算。

示例为增量配置，可通过编辑器提交：

```json
{
  "mentionAuthor": true,
  "mentionTarget": "custom",
  "mentionName": "要提及的昵称",
  "generationProvider": "external",
  "apiBaseUrl": "https://api.example.com/v1",
  "apiModel": "your-model",
  "persona": "喜欢游戏，简洁友好，有具体内容再评论。",
  "replyPersona": "先回应对方的问题，保持耐心，不编造经历。"
}
```

直接替换整个服务器文件时应在现有完整配置上修改，保留所需开关及密钥；文件缺失字段会使用默认值。未知字段、非法类型和无效地址会被拒绝，损坏配置会停止调度，修复后重启宿主。不要把带密钥的配置提交到 Git 或发给他人。
