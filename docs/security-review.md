## 网络出口与凭据

| 代码 | 行为与边界 |
| --- | --- |
| `lib/client.js` | 通过同源 `/heybox/*` 接口向自己的 DSH 宿主获取状态或保存设置；帖子链接在用户点击时打开小黑盒网页。手工输入的 Cookie 和新填写的 API 密钥需要提交给宿主 |
| `lib/index.js` | 平台 API 基地址固定为 `https://api.xiaoheihe.cn`；登录、读取、评论和回复按接口需要携带 Cookie。图片代理限制为 `xiaoheihe.cn` / `max-c.com` 及子域，不附带账号 Cookie。本次关闭上游自动重定向 |
| `lib/login.js` | 二维码申请和轮询使用平台接口；校验二维码 URL 的 origin 和路径。二维码由宿主上的 `qrcode` 生成，没有第三方二维码服务 |
| `lib/generator.js` | 模型输入包括人设、当次帖子标题 / 正文、回复上下文；调用方不将账号 Cookie 作为模型输入。第三方 API 使用用户配置地址，认证头包含对应 API 密钥，禁止跟随重定向 |
| `lib/automation.js` | 远程 API 仅接受 HTTPS，本机回环地址允许 HTTP；配置查询去掉 API 密钥。默认不开启浏览、评论和回复；平台发送前检查限额、冷却与重复记录 |
| `lib/dependencies.js` | 用户主动点击安装后调用 npm；固定安装 `qrcode@1.5.4`，使用 `--ignore-scripts`、`--no-audit`、`--no-fund`，不回显可能包含源认证信息的原始 npm 输出 |

DSH 生成会启动用户指定的 DSH 命令，并使用 DSH 配置的模型。若模型运行在远端，提示词就会传到该服务；用户另行安装的 DSH 插件与模型服务的数据处理不属于本插件可以保证的范围。自定义 API 的域名也由用户选择，不是开发者固定的数据收集端点。

Cookie 必须发送给小黑盒才能执行已授权的账号操作，第三方 API 密钥必须发送给用户选择的 API 才能认证。不能把“没有开发者收集接口”解释为“任何数据都不发送到任何服务端”。

## 文件与命令执行

- 数据位于 DSH 宿主的 `$DSH_HOME/heybox/`，默认 `~/.dsh/heybox/`。云端部署时，这就是用户的云服务器磁盘，不是访问网页的电脑磁盘。
- `state.json` 保存 Cookie；`config.json` 保存人格、调度与 API 密钥；`automation.json` 保存去重、额度、浏览及互动记录。敏感配置文件采用 0600 文件权限，权限的具体效果由操作系统决定，内容不是加密存储。浏览 / 互动记录中也可能包含来信正文。
- `generation.patch.yml` 是局部生成覆盖配置，不修改全局 DSH 配置。生成通过参数数组启动子进程，未使用 shell 拼接；`generation-guard.js` 为此生成进程注册工具禁用规则。用户自行设置的命令路径仍属于受信任的宿主配置，不是沙箱。
- 一键安装将包放到 `heybox/dependencies/`，不安装全局软件，不建立系统 cron / 启动项。调度随 DSH 进程运行，退出宿主即停止。
- `scripts/bili-compat.mjs` 只在用户手工运行维护命令时工作：默认预览，显式 `--apply` 并指定插件目录外的备份路径后才修改指定的 B 站插件源码；常规启动不调用它，也不会自动改写 B 站历史文件。

## 本次发现与加固

1. **旧 Cookie 文件权限过宽**：手工登录和初始化原先使用默认文件创建权限，受 umask 影响可能为 0644。本次改为临时文件 0600 后原子替换；读取已有有效状态文件时也收紧为 0600。扫码登录原有 0600 原子写入保持不变。
2. **账号状态与通用 RPC 缺少浏览器来源限制**：为 `/heybox/state` 的 POST 和 `/heybox/rpc` 补充与其他写接口一致的 Origin host 与 JSON Content-Type 校验；状态响应禁止缓存。这是浏览器来源限制，不替代 DSH 宿主认证。
3. **上游重定向没有再次验证目的地址**：原先允许自动跟随跳转，可能绕过初始地址限制。本次统一设置 `redirect: "error"`，不跟随平台 / 图片请求的重定向。需要跳转的图片将加载失败，后续如需支持应显式逐跳验证目标。

- `npm run check`：语法及 UTF-8 BOM 检查。
- `npm test`：host helpers、前端 smoke 和 35 项 Node 测试；本次扩展用例验证旧凭据权限收紧、手工登录私有落盘、跨站 / 非 JSON 请求被拦截、Cookie 不返回以及上游不跟随跳转。
- `npm audit --omit=dev`：本次查询报告 0 项已知漏洞；它仅覆盖数据库已收录漏洞，不是对所有传递依赖源码的完整人工审查。
- 未使用真实账号发送评论或回复，没有验证所有在线 API 和 CDN 在禁止跳转后的兼容性。
- 本插件不自建独立的 Web 身份认证，使用者必须依靠 DSH 宿主的访问控制；不能将含个人配置的宿主直接无认证暴露到公网。来源校验不拦截能直接访问宿主并构造 HTTP 请求的客户端。
- 本地有相应权限的进程、用户自行配置的 DSH 可执行文件及宿主插件可能读取本地数据。模型供应商可能保留输入，具体取决于用户选用服务的规则。
